السلام عليكم ورحمة الله وبركاته، في حالةٍ واحدةٍ ممكن أن يقوم الـ MITM — الرجل الذي في المنتصف أو الهاكر — بالتلاعب في اتصالك إذا فتحت أي موقع إلكتروني.

يعني أنا الآن كتبت الراجحي.com وحوّلني إلى صفحةٍ أخرى.

عشان نعرف إيش اللي صار هنا، لازم نعرف المتصفحْ يشبك على أي بروتوكول في البداية. أول شيء عندنا بروتوكول HTTP والنسخة المشفّرة منه HTTPS.

أغلب المواقع حالياً في العالم تستعمل HTTPS، لأن HTTP حالياً غير آمن؛ الرجل الذي في المنتصف يقدر يرى البيانات عن طريق عدة ثغرات، يقدر يطلع على البيانات ويقدر يتلاعب فيها ويقدر يحولك لصفحةٍ ثانية. يعني HTTP غير آمن لكنه لا يزال يُستخدم.

بروتوكول HTTP يشتغل على بورت 80، وHTTPS على بورت 443.

السؤال هنا: لما تكتب دومين أي موقع في المتصفح، المتصفح إيش راح يتصل؟ يتصل HTTP أو HTTPS؟ المتصفح ما يعرف إذا الموقع HTTP أو HTTPS. فالمتصفح راح يتصل على HTTP by default بشكل افتراضي.

فجميع المواقع اللي تدعم HTTPS لازم يشغّلون HTTP ويخلّون اليوزر، أول ما يشبك على HTTP، يرسلون له تحويل على HTTPS.
[اظهر مثال] curl

كذا الإنترنت شغال تمام: اللي يبي موقعه يشتغل HTTP يخليه HTTP، واللي يبي HTTPS يشغل HTTP ويحوّل الزوار إلى HTTPS.

الحياة حلوة ولكن هذه الطريقة تسبّبت في ثغرة اسمها SSL Stripping. لأنه في كل مرة أكتب مثلاً الراجحي.com وبدون ما أحدد http أو https — أساساً ما أحد يحدد، الناس تكتب الراجحي.com وخلاص — بتصل بالراجحي عن طريق HTTP ويرجع لي redirect يحولني إلى HTTPS الراجحي.com.
[اظهر مثال]

ولكن المشكلة هنا أن أول request هو HTTP، فهذي ثغرة SSL stripping. الـ MITM — الهاكر — يقدر يحوّلني على صفحةٍ ثانية، يقدر هو بنفسه ياخذ دومين الراجحي.com مثلاً ويسجله. خنشوف الراجحي.com كم يكلف — مو موجود — خنشوف مثلاً نضبّل j، 13 دولار بس. أقدر أخذه وأصير أملك هذا الدومين وأحوّل الضحية إلى هذا الدومين وما رح يلاحظ. راح يجي أن الاتصال آمن وكل شيء، ولكن فعلياً هو مو متصل مع الراجحي. أقدر أرجع له نفس صفحة الراجحي بالضبط وخلاص، أقدر أنا أخذ بياناته تجيني على سيرفري لأن متصل بالسيرفر موقعي أنا.

بقولكم كيف قفلوا هذه الثغرة.

أول شيء ابتكروا الـ HSTS — HTTP Strict Transport Security (أمان النقل الصارم عبر HTTPS).

باختصار: أول Request بيكون HTTP، أوكي. بعدها السيرفر يرد يحولني HTTPS، ولكن بعد ما يحولني ويرسلي صفحة الـ HTML بس، يرسلي هيدر بعد يقول لي: أنت أبغاك تتصل معي HTTPS فقط لا تتصل HTTP، أنا الموقع أستعمل HTTPS ما أدعم HTTP. ما أبغاك كل شوي ترسل HTTP وبعدين أرد عليك وأحوّلك. أنا حولتك المرة هذه بس لأنك أول مرة تزور الموقع، ولكن المرة الجاية اتصل HTTPS بس لمدة سنة مثلاً. والمتصفح يقرا هذا الهيدر ويخزنه في storage يعني داخل ملفات المتصفح هذا الموقع بتتصل فيه HTTPS بس لمدة سنة.

بكذا لو كتبت الراجحي.com بيشبك HTTPS بشكل تلقائي، حتى لو كتبت HTTP الراجحي.com المتصفح بيشبك HTTPS.

بكذا انحلت المشكلة... تقريباً.

إلى الآن فيه سلبيات. يعني زي ما قلت: اتصل HTTP، يرجعني HTTPS، بعدين HTTPS يقولي اتصل HTTPS معاي لمدة سنة، وخلاص. ولكن الآن زيارتي للموقع لأول مرة بالمتصفح يقدر يستغلها الهاكر.
[ويكيبيديا hsts]

أو إنّي مثلاً حملت متصفح جديد وشبكت على شبكة عامة، راح يشبك على HTTP المتصفح. أو إنّي مثلاً شريت جهاز جديد، أو انتهت السنة — مو قلنا إن المتصفح يخزن الموقع لمدة سنة على حسب المدة اللي يرجعها السيرفر؟ بعد السنة هذه راح يشبك HTTP وبيحولني HTTPS وعاد على حسب يرجعلي بعد هيدر يقولي بعد سنة ثانية أو لا.

لكن بيصير HTTP request.

ففي هذه الحالات ممكن الهاكر يحولني إلى موقع آخر ويسرق بياناتي.
